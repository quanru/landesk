# LanDesk 整体迁移到官方 RustDesk 的方案

日期：2026-11-04。状态：已获授权，在 `migration/rustdesk-native` 实施中。用户已明确不需要兼容逻辑，本文据此取消旧协议和旧数据转换。本文替代此前“在官方基线上完整移植 SubnetDesk 协议”的建议；此前评估中的源码证据仍有效。

目标是以官方 RustDesk 的远控、IP 直连和认证为基础，保留 LanDesk 的界面和移动端操作体验。避免长期维护两套远控协议，也不把整份 SubnetDesk 核心文件搬回新基线。

## 方案前提

- 已授权切换分支并实施源码迁移；推送、安装和发布另按当次授权执行。
- 推荐允许上游未启用的源码留在仓库，通过构建与启动边界排除产品不需要的能力。实施时需同步修订现有“必须从源码删除”的范围文档和检查，不能绕过检查。
- 新版统一使用上游协议，不实现当前 LanDesk／SubnetDesk 的协议兼容、协商回退或适配层，用户需要升级两端。与原版 RustDesk 的互通也必须实测后才能承诺。
- 当前已有的原生远控、文件、剪贴板、音频、终端和浏览器访问都进入迁移清单。浏览器网关适配尚未证明可行；它未完成前只能称为原生端候选，不能宣布整体迁移完成。
- 用户已明确选择原生 IP 直连不额外提供应用层会话加密，传输保护由 Tailscale／VPN 等外部网络层承担。保留上游密码认证、手动批准与权限控制，不新增密钥分发、设备指纹握手或强制加密阻断。不得把普通 LAN 连接标成已加密，也不自动修改系统 VPN 配置。

## 基线和历史

当前 LanDesk 基线固定为 758fef56b0d9daf56c44b6bb43cf0e667a8ad262。已评估的官方快照为 55786aaa5709ac0a450aabcf06f9d1fee3119908，正式标签 1.5.1 对应 23e5bb471a040d62f0a6ad52591fb30784265b73。

实施启动时复核官方安全修复，固定唯一主应用提交及全部子模块提交，不使用浮动 master 作为可复现构建输入。正式标签加必要修复与固定快照两种候选，按第一阶段验证选择并记录理由。

继续使用 quanru/landesk，保留现有历史和来源记录，不强推改写历史。正式切换采用可审阅的迁移提交；如果需要记录上游祖先关系，单独设计并核对提交拓扑，不把整批旧差异机械合并进去。用户已明确授权切换分支，当前使用 migration/rustdesk-native；不创建额外工作树。临时验证使用固定源码导出及隔离配置，不改变已安装应用。

现有 common 本地提交 2e7979e 尚未推送。若推送任何依赖它的历史或可构建旧基线，必须先让对应子模块提交在远端可获取。新基线优先使用官方 common 固定提交，是否完全取消 fork 以适配结果为准。

## 功能去向

| 范围 | 新版处理 |
| --- | --- |
| 采集、编解码、桌面控制、文件、音频、剪贴板、游标 | 优先使用官方实现，逐项验证原有能力及平台差异 |
| IP 直连和会话认证 | 使用上游路径，核验密码验证、手动批准和权限控制，沿用上游非加密直连行为 |
| SubnetDesk 握手与认证协议 | 新版不携带；不沿用旧 proto 字段编号，不保留隐式旧协议回退 |
| LAN／Tailscale 地址策略 | 保留私网限定语义，在所有连接和转发入口执行，处理 IPv4、IPv6、映射地址及解析结果 |
| 设备发现、最近连接、收藏 | 优先适配上游机制；只有缺失的体验才复用独立发现模块，不把发现结果当作身份信任 |
| 现代主题、图标、连接面板、状态提示 | 保留产品体验，通过主题和独立控件接入 |
| 虚拟键盘、组合键、鼠标、滚轮、手势 | 保留独立模块，适配上游输入接口，不覆盖整份远控页面 |
| 会话右侧栏、聊天入口、窗口概览 | 保留并按各平台能力适配；已有系统快捷键依赖逐项测试 |
| 终端、端口转发 | 核验权限和目的地址策略；未满足现有能力前不算完整迁移 |
| LAN Web 网关 | 独立适配上游会话接口，保留浏览器访问目标；不为它恢复旧握手协议 |
| 公网 ID、会合、打洞、中继、云账号和同步 | 产品无入口，启动和连接路径不可执行，不允许失败后公网回退 |
| 可下载插件和在线更新 | 延续当前禁用行为；App Store／TestFlight 继续由平台分发 |
| 官网、README、宣传视频和作品集 | 沿用，最终按实际新版界面和下载信息更新 |

先为每项建立“旧版行为、目标行为、实现位置、验证证据、阻塞原因”记录。修复现存虚拟键盘和旋转问题包含在迁移内，不以迁移完成替代功能验收。

## 实现边界

产品改动集中到网络策略、启动配置、品牌资源、Flutter 产品控件和新版配置。尽量通过上游已有接口接入，不引入泛化插件系统或第二套会话框架。

公网功能优先编译排除；无法独立裁剪的共享实现保留源码，但必须证明产品启动、重连、错误处理和转发无法触达。核验不能仅靠搜索域名或隐藏 UI，应结合调用路径检查、故障注入和进程级网络观察。

地址规则覆盖手输、发现、收藏、导入、命令行、深链、浏览器网关和转发入口。域名如开放，连接前验证全部候选地址，并避免校验后再次解析造成绕过。Tailscale 自身是否经中转不属于 LanDesk 的直连保证，也不更改用户 Mac 的网络配置。

第一阶段追踪完整 IP 直连和登录链路。确认连接范围受限、错误密码无法获得会话权限、手动批准设置有效。非加密传输不再构成迁移阻塞；不恢复 SubnetDesk 握手，不开发额外应用层加密方案。浏览器本身要求的 HTTPS／安全上下文保持独立处理，不因本决策关闭。

## 用户升级与数据

用户已明确不需要兼容逻辑。新版按首次使用设计，不实现旧握手、双协议、旧字段映射、配置转换或旧凭据导入。保留的是产品功能和代码资产，不是用户旧数据格式。

保留应用包身份和签名身份，iOS／Android 的 dev.quanru.localdesk 不变。各桌面平台核验安装目录、服务注册和系统权限，以支持正常覆盖安装；这些是发行要求，不是旧协议兼容层。

| 数据 | 新版行为 |
| --- | --- |
| 主题、键盘布局、手势偏好 | 使用新版默认值，用户重新设置，不读取旧偏好 |
| 收藏、最近设备、地址 | 重新发现或添加，不转换旧列表 |
| 主机账号、密码和保存的访问凭据 | 按上游机制重新设置、重新认证，不转换旧哈希或凭据 |
| 设备密钥和指纹 | 不导入旧密钥或指纹，不新增直连指纹确认流程；上游内部身份按其原有机制生成 |
| 原始配置与用户数据 | 留在原处，不主动删除；新版使用独立配置位置，避免误读或覆盖 |

升级说明明确双方都需升级、旧设置不迁移。使用上游正常的无效协议处理及超时机制，不专门为旧版实现探测握手或转换错误消息。异常输入必须正常拒绝，不能无限重试或导致崩溃。

开发验证使用隔离数据。保留旧源码历史和必要发布回执，不额外长期归档旧安装包。不实现自动降级或恢复旧配置的产品逻辑。验证覆盖安装后正常启动、首次设置、新配置持久化，以及原始数据未被误改。

## 阶段、交付和预算

以下为单人等效工程预算，不是 AI 执行时长或固定交付日期。包含开发和定向验证，阶段间不重复计费。外部审核与环境等待另算。

| 阶段 | 工作和交付 | 预算 |
| --- | --- | --- |
| A：官方直连验证 | 固定基线、Mac 被控与 iOS 控制原型，验证登录认证与访问权限，拒绝公网与回退，输出改动边界 | 2–4 人日 |
| B：原生产品迁移 | 主题、品牌、发现、输入控件、侧栏、设置；修复键盘与旋转；适配官方 common | 4–6 人日 |
| C：安装与多端 | 安装身份、首次设置、独立配置、文件／剪贴板／音频／终端／转发，Windows／Linux／Android 验证 | 3–5 人日 |
| D：浏览器网关 | 验证上游接入方式、会话与权限适配、浏览器输入及文件通道、安全验证 | 3–6 人日 |
| E：发布候选 | 全范围回归、签名与升级验证、来源记录、README／官网／下载准备 | 2–3 人日 |

合计 14–24 人日，预留约 25% 风险后按 18–30 人日安排，约 4–6 个工作周。取消旧数据转换后，暂估减少 1–2 人日；多端和浏览器网关验证仍保留，不能因此大幅压缩预算。D 阶段不确定性最高，3–6 人日是预算窗口，不是保证；超出窗口先报告缺口与新估算，不无限投入。A 阶段完成后重新估算全程。

阶段 A 最多先投入 4 人日。成功条件是原版协议真实传输桌面和输入、密码认证和权限控制成立、网络限制有效，且没有大面积重写核心。失败则停止后续迁移，交付具体原因。预算不是后台持续工作的承诺。

现金成本主要由现有设备、签名账号和计算资源决定。默认复用现有环境，不采购设备、不触发付费远端 CI。需要 Windows 真机或云环境时先列费用并取得当次授权。人民币预算可用“18–30 × 实际人日单价 + 外部费用”估算；当前没有可靠单价，不给虚构报价。模型调用成本也不从人日直接换算。

## 验收矩阵

- 第一轮为 Mac 被控、iOS 控制，必须看见真实桌面并完成无敏感内容输入。
- 桌面被控端覆盖 macOS、Windows、Linux，移动控制端覆盖 iOS、Android。Android 被控能力按现有支持范围验证；不承诺 iOS 新增被控能力。
- 原生连接覆盖 macOS、Windows、Linux、iOS、Android 的受支持控制端，以及浏览器网关。按改动涉及的协议、权限和平台边界选择交叉组合；每个声称支持的组合至少连接冒烟，重点组合跑完整输入和传输。
- 虚拟按键在 iOS／Android 的横竖屏都有明确入口，验证组合键、多点触控、抬手释放、切后台松键、系统键盘共存、硬件键盘以及画面缩放和旋转后的坐标。
- 网络覆盖普通 LAN、已有可用 Tailscale 路径、断网、错误密码、手动批准、协议不匹配、IPv6、发现不可用及重连。测试公网地址被拒绝，不实际连接无授权主机。
- 文件和剪贴板验证取消／恢复、大数据、路径与覆盖保护、权限关闭后行为。保留最近补充的安全回归，对照新上游确认已覆盖、仍适用或需重写，不能机械 cherry-pick 32 个提交。
- 浏览器验证身份、授权、HTTPS／来源校验、会话隔离、连接关闭与输入释放，禁止认证信息进入 URL 或日志。
- 覆盖安装后验证首次设置、新配置持久化及密码认证，确认不读取、不覆盖旧配置。不实现旧版兼容测试矩阵；仍验证无效协议输入被安全拒绝。

构建和运行按 dev-gate 额度执行，本机不无条件全量测试。Windows 专属行为必须用 Windows 环境验证，Linux 同理。每份证据记录源码与产物、平台、设备／模拟器类型及验证范围，关键 UI 提供真实截图。

## 发布与完成条件

实施迁移与正式发布分开授权。发布候选通过后，再按授权准备签名安装包、TestFlight／商店提交、固定下载与官网信息；商店处理和审核等待不算代码完成。保留各平台真实飞书主下载和官网备用链接，平台商店沿自己的安装机制，核验版本和哈希，不编造下载入口。

官网唯一维护位置仍为 studio 的 apps/landesk-site，作品集为 apps/shop-site。获准推送网站 main 后核验自动部署。应用仓库推送不能当作官网已上线。

整体迁移完成必须同时满足：支持范围内全部原生端通过、浏览器网关完成、网络与安全验收通过、升级流程可用、键盘与旋转问题验收通过、所有功能清单项有结果。若决定删减功能，单独记录用户决定，不能用“后续再做”替代完成。

保留 RustDesk 和实际复用的 SubnetDesk 来源、许可与作者记录。新基线不意味着可以移除仍复用代码的 credit；公开文案按最终真实来源描述。

## 后续维护

维护一份自有改动清单，标明动机、上游文件接入点和回归测试。常规升级按固定版本合并与验证，安全修复优先核对；无需逐提交追平所有上游历史。

迁移后用一次真实上游升级检验维护收益，记录冲突文件、耗时与回归问题。若核心改动再次扩大，先收敛边界，不以继续搬整份文件解决。当前不承诺每版固定节省多少人日。
