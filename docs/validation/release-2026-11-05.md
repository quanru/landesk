## 发布门槛

流水线先上传 Actions artifacts，没有公共 Release 写权限。构建完成后核验实际包名、版本、签名和 SHA-256，完成候选运行验证后再创建 GitHub prerelease。macOS 云端产物仍须本机发行签名及公证；Windows 暂无签名配置，必须明确标注 unsigned。构建成功不代表端到端远程连接验证成功。

原生预览版使用官方 RustDesk 协议，不兼容 legacy 协议；虚拟按键、局域网入口和 LanDesk 主题保留。公网中继、账号服务和浏览器远程入口不属于本次版本。

## 本轮故障与恢复

- iOS `font-subset` 阻塞于 stdout write，采样确认后关闭 icon tree shaking，保留完整图标字体，复用编译缓存归档成功。
- Xcode export 的系统 rsync 子进程误用 Homebrew rsync，导致 `--extended-attributes` 不兼容。仅给导出进程限定系统 PATH 后成功；未修改系统设置。
- 初次外部审核资料缺少四项联系人字段，补齐后 readiness 通过。
- Android recovery 首次缺少 Java 安装目录，补齐 Java 17 后恢复；证书输出 sed 捕获组已修正。
- Linux 干净验证环境先后缺少 EGL、OpenGL ES 与 xwininfo，分别补齐 libegl1/libgles2/x11-utils 后真实窗口检查通过；未改动应用二进制。
- Intel Mac 初次签名尝试先签主程序，触发未签 service 校验；签名器改为先嵌套组件、最后整个 app，通过 strict/deep 检查和 Apple 公证。
- 本机 GitHub 大文件上传慢，新增 source-bound draft 上传 workflow，Windows/Linux/Android 由 Actions 直接传入草稿；Mac 仍上传本机公证后的精确文件。
- 所有本机重编译经过 dev-gate，真机验证经过 device-ios 会话锁，验证后已释放。

## 后续发布入口

`gh workflow run landesk-preview.yml --ref main` 构建固定提交；完成后使用 `landesk-verify.yml` 检查 Windows/Linux 实际窗口。`landesk-publish-artifacts.yml` 只向绑定源 SHA 的现有 draft prerelease 上传经过构建的 Windows/Linux/Android 文件，不自动公开。macOS 签名、公证与 iOS TestFlight 仍在本机使用现有 Apple 凭据完成，没有把 Apple 私钥上传到 GitHub。最后核对版本、签名、运行证据及服务端 SHA-256，再公开预览版并更新官网。Android recovery 只用于复用同次 source/native core；正常发布使用完整 preview 构建。
